### 9.1 A1–A4 reconstruction replaces the sales-based I0

The previous initial stock was "first L weeks of sales × safety factor". Rue rejected
that definition. The root cause was upstream: pre-release shipments were counted as
`before_release` **exclusions** and discarded, although they are the opening
allocation (78% of pairs are first stocked before release). Retention now keeps every
event at lifecycle week ≤ 1 as `opening_by_key`; the exclusion counter reports
`opening_stock` instead. Sample: 541 pre-release + 7 release-week events = 548.

| Assumption | Encoding |
|---|---|
| A1 | `stock_t` floored at zero; the unfloored minimum is still published |
| A2 | opening = restocked-to-release units × alpha (0.5 / 1.0 / 1.5, main 1.0) |
| A3 | smallest extra opening stock that keeps the unfloored path ≥ 0, **recomputed per alpha** |
| A4 | no restock on or before release ⇒ opening 0 until the first observed restock |

A1/A3/alpha are separate config keys (`inventory.floor_at_zero`,
`inventory.negative_correction`, `inventory.opening_stock_alpha`), so §7.7 can sweep
them without call-site edits. The bundle now carries the policy, the base opening
stock, the A3 correction, `min_raw_stock`, `negative_weeks` and
`would_go_negative`; the chapter pack exposes them as labelled figures.

**Recorded figure movement (sample, self-test only):**

| Figure | v1.4 | v1.5 | Cause |
|---|---|---|---|
| Demo I0 | 33.00 (`lead_time_demand`) | **487.00** | A2 opening 35 × α1.0 + A3 correction 452 |

## 10. R0–R4 scenario ladder (2026-11-22, main setting only)

The ladder was a **new subsystem**, so it was filed as a requirement delta
(`.codeartsdoer/specs/visuelle_proto/scenario_ladder_delta.md`, R-S1…R-S9) before any
code was written. The specification came from the Chapter 7 draft, not from
invention: the six roles, the isolation rule, the week 1–2 / week 2 / weeks 3–12
timeline, the "remove the retailer's post–week-2 restocks" rule and the metric
formulas.

**Implemented.** `src/replenish/scenario.py` (settings, pair, per-pair simulation,
scenario and ladder runners) and `src/replenish/scenario_metrics.py` (fill rate,
stock-out rate, overstock ratio, turnover, weeks of cover, optional cost index). The
pipeline runs it as **S10b** after the sealed test read, publishes `bundle.scenarios`,
`output/<run>/scenarios.csv`, and five chapter figures per scenario
(`scenario.fill_rate` and friends, partition `test:<scenario>`, REP-10/11).

**Rule as coded.** `P = L + R`; target at the end-of-week review
`S_t = Σ week-2 forecast over weeks t+1..t+P + z·σ_e·√P`;
`Q = max(0, S_t − position)`, position = on-hand + on-order; an order placed at the
end of week `t` is received at the start of week `t + L + 1`; reviews at weeks 2–11
only. R0 replays observed restocks, R0b never reorders, R1 = the `naive_reference`
model, R2 = `category_curve`, R3 = the chosen model, R4 = actual future sales with
σ_e = 0. Rule, lead time, review cycle and service level are identical across
R1–R4; only the forecast and its validation σ_e differ (R4 = 0), which is the
isolation the draft requires.

**Evidence.** 322 passed, 3 skipped (`real data absent`); `run_pipeline` prints
`[S10b]`; `scenarios.csv` carries R0, R0b, R1–R4; settings echo L=1, R=1, P=2,
z=0.95, label `simulation under stated assumptions`; `cost_index` is **null** with
the reason "cost ratio cu:co is a §7.7 grid value, not yet locked" (0.1).

**Hardening after the first run (2026-11-22).** Four silent-failure paths were
closed: the ladder now refuses a forecast origin other than week 2 (it is defined
for 2-in/10-out); every forecast must cover the full horizon; a scenario with no
forecast source is recorded in `scenarios.unavailable` instead of silently vanishing
from the table; and `bundle.validate_complete` now requires `scenarios` and
`error_scale`, so a pipeline regression cannot publish a bundle without the ladder.
The pack also states the main setting (`scenario.count`, `scenario.service_level`,
`scenario.cost_index_status`, `scenario.unavailable`), and the console's
replenishment panel renders the ladder table with the same caption. Tests: 322
passed, 3 skipped.

**Recorded sample artefact.** On the generated sample, every forecast arm reaches
fill 1.000 and stock-out 0.000, while R0b is 0.990/0.014. That is the A3 opening
padding again: all arms start from the same non-negative reconstruction, so the
sample's synthetic restocks leave enough stock that reorder timing barely bites. The
ladder is a measurement instrument; its sample values are not a result, and the
real-data differentiation is expected to come from the real restock/sales balance.

**Not done, deliberately.** R1–R4 *comparisons* across the grid, cost-ratio runs and
sensitivity execution all wait on the §7.7 sweep being run; the reported R0–R4
numbers remain Linda's deliverable. (Superseded on 2026-11-22 by §11: the grid is
now locked and the error-slicing half is built.)
